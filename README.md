# Realms of Ash

A turn-based fantasy medieval kingdom builder. Up to **4 players** share a hex tile map, each managing their own kingdom — expand territory, grow an economy, train armies, and fight to be the last kingdom standing.

Sessions are designed to last roughly **one hour** and are played with friends in private lobbies.

> For the full design, see [`DOCS/game-design.md`](DOCS/game-design.md) and the per-system documents in [`DOCS/Game/`](DOCS/Game/).

### Backend Architecture

Clean architecture with strict layering: **Base → Domain → Application + Infrastructure → API**.

- Feature-based folders inside each project (`Auth/`, `Game/`, `Map/`, `Military/`, `Combat/`, …)
- `BaseRepository<T>` + lazy Unit of Work + service layer + `Result<T>` pattern
- Reference data lives next to its domain (`TerrainType` in `Map/`, `UnitType` in `Military/`, …)
- Nullable warnings are treated as errors (see `Backend/Directory.Build.props`)

## Core Game Loop

1. Players log in and join or create a lobby.
2. Host starts the game (minimum 2 players) — the hex map generates and each player receives a Castle plus 7 starting tiles.
3. Each round runs through phases: **Action → Battle → Income → Round End**.
4. During the Action Phase players spend action points to build, upgrade, train armies, or declare attacks.
5. Battles resolve in the Battle Phase via pre-set lineups (3v3 / 5v5) and dice-driven combat.
6. The Income Phase generates resources, pays upkeep, heals armies, and checks win conditions.
7. The game ends when one kingdom remains, or when round 100 is reached.

### Key Systems

| System | Summary |
|--------|---------|
| Turn structure | Round-based: action → battle → income → end |
| Combat | Round-by-round resolution with pre-set lineups, no rock-paper-scissors |
| Resources | 5 types (Gold, Food, Wood, Stone, Mana) generated by buildings |
| Buildings | 6 chains (5 resource + 1 military), territory expansion on placement |
| Army types | 6 types with distinct risk profiles |
| Factions | 4 factions with unique strengths, weaknesses, and starting bonuses |
| Slot machine | Gold-sink gambling for extra action points |
| Win condition | Elimination — lose your Castle, you're out |
| Map generation | Hex grid, anti-clustering terrain, fair starting positions |

See [`DOCS/Game/`](DOCS/Game/) for full rules per system.

## Getting Started

### Prerequisites

- [.NET 10 SDK](https://dotnet.microsoft.com/download)
- [Node.js](https://nodejs.org/) (LTS recommended)
- [Docker](https://www.docker.com/) — for the PostgreSQL instance

### 1. Start PostgreSQL

The default development connection string (see `Backend/API/appsettings.Development.json`):

```
Host=localhost;Port=5432;Database=postgres-dev;Username=postgres;Password=postgres
```

A quick way to start a matching database:

```bash
docker run --name roa-postgres -e POSTGRES_PASSWORD=postgres -p 5432:5432 -d postgres
```

EF Core migrations and seed data run automatically on backend startup (`MigrateDatabase` and `SeedData` are enabled in `appsettings.Development.json`).

### 2. Run the Backend

```bash
cd Backend
dotnet restore
dotnet run --project API
```

### 3. Run the Frontend

```bash
cd Frontend
npm install
npm run dev
```

Frontend scripts:

| Command | Description |
|---------|-------------|
| `npm run dev` | Start Vite dev server |
| `npm run build` | Type-check and build for production |
| `npm run lint` | Run ESLint |
| `npm run preview` | Preview the production build |
